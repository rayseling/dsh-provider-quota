# Agent Note: 一道门要证明什么，以及怎么修它

Status: implemented

2026-08-25

## 问题

这套门禁被对抗性复查过两轮：第一轮 27 条发现，第二轮又 12 条。
第二轮里有 6 条属于同一个形状——**第一轮那个样本堵上了，机制没堵**：

- `/\w+'s/u` 让扫描器进入字符串模式的问题修了，但 `used / limit` 没修
  （空格后面也被当成能起正则），一行普通的带空格除法就能让两道门对整个文件失明；
- `requestImageMaxBytes: undefined` 拒了，但 `const X = undefined` 没拒；
- 一个编出来的符号名从**注释**里解析的路堵了，从**字符串字面量**里解析的路没堵。

还有一类更糟的：门本身把一个假事实钉在原地。`catalog-wording` 曾要求文案里必须出现
`/v1/models`——而 harness 根本不提供这个路由。把文案改对，门当场变红。

## 决定

四条，写进 `AGENTS.md` 作为常驻规则：

1. **断言行为，不断言字段存在。**
2. **断言外部可观测的事实**，不断言被测对象自己的说法。
3. **新加门或回归测试，先证明它会红**：塞回 bug → 变红 → 还原，并在汇报里写明。
4. **修门时修机制，不修那个样本。** 收到一个绕过样本，先问「这一类还有哪些写法」。

配套的结构决定：每道门的 collector 都收在 `scripts/check.mjs`，
`test/check.test.js` 给每条拒绝规则配好样本和坏样本，
用 `assert.deepEqual` **逐字**断言整个违规数组。

## 考虑过的方案

- **只断言「找到了违规」，不逐字断言消息。** 没选：门的产品**就是那段文案**——
  agent 靠它决定下一步怎么改。文案退化（行号错了、少了补救办法）不会有任何东西发现。
  逐字断言同时钉住三件事：违规被找到、行号对、没凭空多出一条。
- **门只报第一条违规，快速失败。** 没选：修门报错是「看报错 → 改 → 重跑」的循环，
  每轮都要重读上下文。一次列全，一轮就能做完。
- **给门加一个「宽松模式」/`allowFailure` 逃生开关。** 没选：九个检查的仓库里，
  非阻塞的唯一形式是**不写进列表**。移植一个逃生开关，迟早有人去扳。
- **要求文案里出现某个固定 token 来锁住语义。** 部分保留，但学到了代价：
  token 必须是**真的**。`/v1/models` 那次，一道门把一个编造钉了下来。
  现在要求的是 `catalog` 和 `listModels`，两个都经得起 grep。

## 后果

- 报错文案变成受测资产，改文案要同步改测试。这是刻意的摩擦。
- 门可以有已知漏洞，但**必须写出来**：`AGENTS.md` 的「门盖不到的地方」列着
  `ctx['settings']`、去掉反引号、`Name.member` 的后半截等等。
  一道门证明不了的事，比它证明得了的事更需要写下来。
