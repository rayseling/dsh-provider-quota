# 额度跟着会话当前的模型走，不是一个设置项

`9bbf651` · 2026-08-25

## 问题

卡片一直只能改一个数字。而人打开它，多半是想知道另一件事：**还剩多少。**

## 决定

卡片和会话标题旁的胶囊都显示额度，读同一份宿主侧数据。
**显示哪一个额度，是当前会话 provider 的函数，不是一个设置项**：
openai-codex 给周窗口，opencode-go 给 5h/7d/1m，deepseek 给账户余额，
其余一律不给——而不是把另一个账号的数字挂到标题上。

读取留在宿主侧，走 Connection 的请求信任和浏览器会话认证，不自建 HTTP 路由：
浏览器拿到的是窗口或余额加一个时间戳，access token、API key、账号 id 一个都不过界。
每个 provider 有自己的缓存行，键是产生它的那份凭据，所以切模型不会把甲账号的数字端给乙账号。
模型请求和额度读取共用一个 pi-ai resolver，过期 token 是在文件锁下转一次，
而不是两个调用方争着转。

## 考虑过的方案

- **做成一个设置项「显示哪个 provider 的额度」。** 没选：它和会话当前的模型必然会不一致，
  而不一致的那一刻，界面上就是一个属于别的账号的数字。让它跟着模型走，这个状态不存在。
- **自建一条 HTTP 路由给浏览器调。** 没选：那要自己做 Host/Origin/fetch-site 的信任判断，
  而 Connection 已经做了，并且它的注册跟随本插件的 fiber，卸载即失效。
- **把凭据下发给浏览器，让前端直接问上游。** 没选：那把 token 放进了浏览器，
  换来的只是少一跳。这条不是权衡，是底线。
- **一个全局缓存。** 没选：切模型时会把上一个 provider 的答案当成当前的。
  缓存行按凭据分开之后，这件事在结构上不可能发生。
- **上游没有周窗口时报错让用户重试。** 没选：「重试」是一句不改变任何结果的建议。
  没有窗口是一个**真实的答案**，读作 ready-and-empty，面板照实说。

## 后果

- 额度端点（Codex 的 `wham/usage`、OpenCode 的 `/usage`）都是未公开接口。
  上游一改，显示变成「额度暂不可用」，模型请求不受影响。这是刻意的取舍。
- 从设置里读路由配置这件事，后来咬了一次
  ——见 [`0002`](../postmortems/0002-property-accessor-without-inject.md)。
